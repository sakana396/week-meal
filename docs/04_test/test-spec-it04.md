## 1. 方針

以下は反復全体のケース。#84 の単体部分は実装し、#85 以降の画面ケースは設計段階のままとする。実装 Issue で固定試料・手計算値・文言・保存原文・試験方法を具体化する。`src/core/` は Vitest の表駆動テストで入力不変と分岐を確かめ、画面は Playwright の mobile / desktop で確かめる。性能の時間超過は CI では記録のみ、計測不能・機能不整合は失敗とする。公開 URL の Lighthouse は手動の記録であり、ここで実施済みとはしない。

## 3. 削除した要求と旧ケースの扱い

SRS v0.5 で FR-ING-11・12 は削除された。旧仕様書と実施記録は履歴として消さず、次を IT04 の実装から外す。実装 Issue では旧仕様書の該当行に「IT04 で廃止」と追記し、旧テストコードの使い切った操作を削除・置換する。

| 旧ケース | 扱い | 置換先 |
| --- | --- | --- |
| TC-NFR-03-01〜03 | IT03 の性能試験にある「使い切った」操作は IT04 で削除に変更。旧仕様書の記録は残す | TC-NFR-03-04（買い物単位の性能試験） |
| TC-FR-ING-11-01 | 廃止。「使い切った」にする操作をなくす | TC-FR-ING-17-01、TC-FR-NUT-07-01 |
| TC-FR-ING-11-02 | 廃止。ホームの使い切った行・戻す表示をなくす | TC-FR-ING-19-01、TC-FR-NUT-07-01 |
| TC-FR-ING-12-01 | 廃止。使い切った切り替えによる取り消しをなくす | TC-FR-ING-20-01（買い物削除の確認） |

旧試験で `usedUp` を前提にしたケースは、買い物単位の入力と期待結果に変更して検証する。版 3 の保存検査は旧ケース ID を保持し、`src/core/storageRegression.test.ts` で破損・未来版・行の個別除外・台帳・版 1→2→3 の移行を検証する。登録・個数・取り消しは `src/core/basketRegression.test.ts` と `basketSessionRegression.test.ts` で旧ケース ID を保持する。旧仕様書の行は並べ替えない。

| TC-FR-ING-01-03・09 | 前の買い物の同じ食品を引き継がず、今の買い物で個数 1 から登録・通知するケースへ変更。使い切った解除は IT04 で廃止 |
