## 生成・値の確認と設計への提案

原典 Excel はローカルに見つからず、ネットワークも使わない条件のため、原典からの再生成と原典の成分値の照合は未実施。原典を入手できる環境で `npm run convert:mext` を実行し、維持した行の値を照合する必要がある（QA-09）。

今回の提案は、原典の再取得まで既存同梱データを入力として、既存の変換スクリプトの `select_foods` と `load_selection` で再絞り込みする方法。変換スクリプトの実装は変更しない。1,238 件から上表の 9 件だけを除外して 1,229 件とし、保持する全行が変更前と完全一致することを比較した。これは既存データを変更していない確認であり、原典から正しく生成されたことの確認ではない。

## 保存データへの影響と人の査閲

除外番号を参照する既存の保存行は、ADR-0004 の既存の読み込み処理（`parseEntry`）で不明な食品として除外される。通知は除外件数だけで、食材名は出ない。原文の退避は保存データ全体が `corrupted` の場合だけなので、この個別の行の除外では原文は退避されず、次の保存で除外された行は失われ、元に戻せなくなる。公開していない（E-54）ため、影響は開発者本人のブラウザに保存されたデータに限られる。今回、保存の実装・バージョンは変更しない。

除外リストの妥当性、維持したキャッサバ・くず・さつまいもでん粉などが普段の買い物に合うか、およびこの保存行への影響を査閲してほしい。液汁 07036 を果肉 07035 へ移すなどの番号の移行や、捨てる行の退避は今回実装しておらず、対策が必要かを本人の査閲点とする。また、06369「だいこん おろし水洗い」も単体で買う形ではないため、今後の除外を検討する査閲候補とする（今回は維持）。原典からの再生成・照合は原典を使える環境で別途確認が必要。
