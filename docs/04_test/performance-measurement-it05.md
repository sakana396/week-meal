# IT05 日付変更の性能計測

対象: NFR-03 / DES-PER-05, 06 / TC-NFR-03-05。

## 根拠と対策

IT04 の実測では CPU 4 倍・100 行・別履歴 100 件の日付変更が最大 123.3 ms だった（[IT04 の記録](performance-measurement-it04.md)）。変更前の画面コードでは、状態の参照が変わると最新の買い物を再分析し、詳細の分析は描画ごとに再計算していた。日付変更では `Shopping.items` の参照が変わらないため、DES-PER-05 の順 1・2 に従い、行・手入力食品・属性の参照で分析結果を覚えるようにした。ホームで最新の日付を古くする操作では、切り替え先を詳細で開いていない場合もあるため、ホーム表示後に次に最新となる買い物の分析を覚える。保存を描画後へ移す対策は、保存の実測内訳がないため適用していない。

## 計測方法と記録

`e2e/performance.spec.ts` の TC-NFR-03-04・05 は、IT04 と同じ各条件を 1 つずつ実行する。日付変更では `dateChangeDetail` に reducer・分析・保存の各呼び出しの開始位置と所要時間を入れる。分析の記録がない回はキャッシュが使われた回である。描画とブラウザのスケジューリングは個別に計測していないため、クリックから判定描画までの全時間と内訳を時刻で照合する。候補は判定と別時計で扱う。各条件の `performance-it05-summary.json` に開始・終了の UTC 時刻、コミット、作業差分の有無、GitHub 情報、OS・CPU・Chromium の版、CPU 制限と操作別の全値・最大値を入れる。100 ms 超過は記録し、revision・保存・画面の不整合や計測不能は失敗にする。

計測コマンドは `npm run test:e2e -- --project=performance --workers=1 --output=test-results/performance`。機能 E2E や Lighthouse と同時に流さない。

この worktree のサンドボックスでは性能 E2E を実行していない。IT05 の数値と全条件の合否は未実測である。

## 新しい操作の扱い

重さの入力・量の種類の切り替え・貼り付け 30 件は、NFR-03 と IT05-PLAN 3.1 が定める操作に含まれないため、TC-NFR-03-05 には追加しない。これらを診断用に測る場合は、画面実装が揃った後に別 Issue で扱う（DES-IT05 8 章）。
