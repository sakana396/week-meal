## 1. 方針

- 単体テストは Vitest（`src/**/*.test.ts`）、E2E テストは Playwright（`e2e/*.spec.ts`）。各ケースの方法は期待結果に書く。
- 既存ケースの連番の続きから採番する。同じ ID の既存ケースを強化する持ち越しは 2.2 に分け、新規ケースとして重複計上しない。
- 以下は設計段階の骨組み。実装 Issue で入力食品番号・成分・設定・手計算した値、画面の期待文言、計測条件を具体化する。まだ通過したテストではない。正常・境界・異常を表駆動で確かめる。必要なケースはこの続きに追加する。
- E2E は既存の mobile（360×740）と desktop（1280×800）の両方。性能計測だけは DES-PER-01 の専用 `performance` project を `--workers=1` で別実行する。通常の 2 project は性能ファイルを除外する。CI の時間超過は記録のみ、計測不能・revision 未更新・機能の不整合は失敗。NFR-03 の 100 ms の合否は合意した実機相当条件で判定する。
- core の入力の不変性と、候補の仮定を実際の集計に混ぜないことも検査する。全検証コマンドと E2E の通過、core の命令網羅率 80% 以上を実装時に確認する。
