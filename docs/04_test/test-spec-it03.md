## 1. 方針

- 単体テストは Vitest（`src/**/*.test.ts`）、E2E テストは Playwright（`e2e/*.spec.ts`）。各ケースの方法は期待結果に書く。
- 既存ケースの連番の続きから採番する。同じ ID の既存ケースを強化する持ち越しは 2.2 に分け、新規ケースとして重複計上しない。
- 以下は設計段階の骨組み。実装 Issue で入力食品番号・成分・設定・手計算した値、画面の期待文言、計測条件を具体化する。まだ通過したテストではない。正常・境界・異常を表駆動で確かめる。必要なケースはこの続きに追加する。
- E2E は既存の mobile（360×740）と desktop（1280×800）の両方。性能計測だけは DES-PER-01 の専用 `performance` project を `--workers=1` で別実行する。通常の 2 project は性能ファイルを除外する。CI の時間超過は記録のみ、計測不能・revision 未更新・機能の不整合は失敗。NFR-03 の 100 ms の合否は合意した実機相当条件で判定する。
- core の入力の不変性と、候補の仮定を実際の集計に混ぜないことも検査する。全検証コマンドと E2E の通過、core の命令網羅率 80% 以上を実装時に確認する。

### 2.3 色の検査条件と計算式（#55、DES-COL-01, 02）

TC-FR-UI-06-01 は下限比 0・0.5・0.699999・1・2 を下限規則と PFC の両方で検査する。TC-FR-UI-06-02 は high・ok・unknown、上限規則、欠損・負値・NaN・無限大・PFC 下限 0 を検査し、比なしの不足でも両画面に文字と栄養素名が残ることを静的描画で確かめる。TC-FR-BAL-07-07 の下限比そのものの異常値は既存の表駆動テストを参照し、色への適用は TC-FR-UI-06-02 で検査する。

TC-FR-UI-06-03 の E2E は検査専用の手入力 3 品目・主食なしを使い、下限規則の比 0.699999 / 0.7 / 0.700001 と PFC 下限比 0.99999 / 1 / 1.00001 で判定と色の境界を確かめる。ホームと詳細のバッジ、適正・不明、偏りがあるホームの判定枠の枠線・背景が中立色であること、全状態と判定対象外の棒・値の目印・範囲帯を検査する。TC-NFR-07-01 は強制カラーでも両画面の不足・過剰・栄養素名と詳細の不明の文字を確かめる。mobile / desktop の両設定を対象とする。

コントラスト計算の一次資料は W3C [WCAG 2.2 の相対輝度](https://www.w3.org/TR/WCAG22/#dfn-relative-luminance)、[コントラスト比](https://www.w3.org/TR/WCAG22/#dfn-contrast-ratio)、[達成基準 1.4.3](https://www.w3.org/TR/WCAG22/#contrast-minimum)。この作業はオフラインのため一次資料の本文再取得はしていない。4.5:1 は DES-COL-02 の検査目標として用い、アプリ全体の規格適合を示すものではない。

8 bit の各 sRGB 成分を 255 で割った値を c とし、c ≤ 0.04045 なら c / 12.92、それ以外は ((c + 0.055) / 1.055)^2.4 に直す。相対輝度 L = 0.2126 R + 0.7152 G + 0.0722 B、黒文字との比は (L + 0.05) / 0.05。赤〜黄の緑成分 0〜255 全通りと紫 #d8b4fe を検査し、丸め前の比を 4.5 と比較する。計算結果と実行状況は traceability の #55 の行に記録する。
