## 2. 貼り付け（DES-RCP-11）

DES-RCP-09 の前処理、桁区切り除去、長さ制限、失敗時の扱い、確認一覧と登録の規則を維持し、分割走査だけを次のように拡張する。空白は NFKC 後の半角空白またはタブの連続をいう。

1. 桁区切り除去後の物理行を空白でトークンに分け、左から一度ずつ読む。コンマのないトークンは名前に蓄える。名前には空白を含められるがコンマは含めない。
2. コンマを 1 個含むトークンでは、その前までを蓄積した名前の末尾にする。名前が空なら失敗。コンマの後が空でなければその残りを量とする。空なら直後の次のトークン全体を量として消費する。次がない場合は失敗。
3. 量は DES-RCP-09・10 と同じ符号付き数値・分数と、空白なしで直後に続く既存の単位・g・kg・ml、または単位なしの数値全体に一致しなければ失敗。消費した量のトークンにコンマがあっても失敗。成功なら組を確定し、名前の蓄積を空にする。数値と単位の間の空白は分割時に認めない。
4. 余分なコンマ、末尾の名前の余り、不正な量、組が 1 個以下のいずれかでは全体を分割せず、従来どおり元行を 1 行解析に渡す。部分的に救済しない。2 組以上なら各組を元の順で解析する。組の文字列はコンマと量の間の空白を含み、境界の空白を除く。長さはこの文字列で測る。

例: `豚肉, 1 鶏卵, 1` は `豚肉, 1` と `鶏卵, 1`、`豚肉,1 鶏卵, 1` も 2 組。`豚肉, 1 個 鶏卵, 1` の 2 組目の名前は `個 鶏卵`。`豚肉, 1,000g 鶏卵, 1` は桁区切り除去後に 2 組。`豚肉, 鶏卵, 1` は分割失敗、`ロース ハム, 1` は 1 組なので従来解析へ渡す。空白を飛ばして量を探し続けない。各トークンと文字を定数回だけ扱い、後戻りや行全体の繰り返し走査をしないため入力長に線形。既存の 4000 文字・組 200 文字の制限と、分割不能行の 200 文字制限を保つ。

## 3. 性能再計測（DES-PER-08）

IT08 最終版を含む、計測時点のコミットと未コミット差分を記録する。既存 `e2e/performance.spec.ts` の 100 行・CPU 4 倍の試料（覚えた食品 100 件、360 × 740 px）で、登録、候補登録、増加、減少、削除を対象とする。日付変更は対象外（E-153）。候補登録は既存どおり候補ボタンにフォーカスし Enter で発生した click を使う。各試行で試料を初期化し、準備・スクロールと削除の詳細を開く操作を時計の外に置く。クリック受信から判定 commit 後の 2 回目の描画までを測り、候補の計算・反映の別時計は加算しない。

計測専用の作業時間を確保し、他の worktree のテスト・ビルド・ブラウザー操作など自分たちの作業を止め、同一 PC・ブラウザー・電源条件で性能テストを `--workers=1` で単独実行する。OS 等の負荷を完全に排除できるとは仮定しない。各操作 5 回を 1 組として独立に 3 組実行し、毎組の全生値と最大値、3 組の最大値の最小・最大、環境、日時、コマンド、コミット、差分、異常や並行負荷を記録する。計測不能・機能不整合は失敗として原因を記録し、欠測を成功扱いしない。中断・再実行も理由と全結果を残す。

**判定に使う値**は各組の各操作の 5 回の最大値。各最大が 100 ms 以下か超過かを個別に示し、1 回でも超過した事実を後の計測で取り消さない。**ぶれの記録**は全生値と 3 組の最大値の範囲であり、これを閾値への判定から除外しない。IT08 の 198.0 ms と 64.7 ms は日付変更の同条件の別計測の最大値であり、候補登録のばらつきの実測値ではない。3 組でも将来の全操作の保証や原因の特定、数十 ms の改善・悪化の断定はできない。CPU 4 倍は SRS の模擬条件で、実機の実測ではない。性能テストの成功と時間条件の達成は分けて報告する。

## 4. 食材行（DES-UI-53）

ホームと前の買い物の名前ボタンに下線と開閉状態に応じた下向き・上向きの山形を常時表示する。山形は装飾として読み上げず、既存の「詳細を開く／閉じる」と `aria-expanded` を保つ。名前の省略、44 × 44 CSS px 以上の操作領域、360 px で横スクロールなし、フォーカスの可視表示を維持する。山形の幅も含めて長い名前・量と同名の詳細名を実寸で検証する。

既存の `fullName`（表示名と、同名時に得られる詳細名）を詳細内の単位群、各単位切り替え、重さ入力のラベル、削除の読み上げ名にも使う。例: `豚肉 ロースを削除`、`豚肉 バラを削除`、`豚肉 ロースの重さ`、`豚肉 ロースを g に切り替える`。詳細名がない行は従来の表示名を使う。詳細名まで同じ、または取得できない同名行が複数ある場合は、同じ表示名の現在の表示順の 1 始まりの番号を全操作の名前に付ける（例: `豚肉 手入力 1 行目`、`豚肉 手入力 2 行目`）。番号は同名行全体の順で、判定は表示名ごとに詳細名を含む名前が重複するかで行う。番号は表示順の変更・削除で変わり得るが、保存 ID や React key は変更しない。名前・増減も同じ識別名を使う。表示名が一意なら既存文言を維持する。

既存の開閉、重さの不正入力時の焦点、単位切り替え後・削除後・取り消し後の焦点、閉じた詳細の非描画と `aria-controls`、行の key と保存形式を維持する。登録画面と 3 タップ以内の経路は変えない。

## 5. 共通の検証と互換性

解析は表駆動の単体テスト、画面は mobile・desktop の E2E で確認する。既存の 1 行解析、負数、桁区切り、行内順と確認一覧の key、開閉・焦点・寸法・登録の試験を維持する。性能の時間超過は記録し、計測不能と機能不整合は失敗にする。

## 6. 計測記録

実装時に `docs/04_test/performance-measurement-it09.md` に 3 章の条件・全生値・各組最大・範囲・結論を残す。IT08 の 121.2 ms の超過と再計測の 79.9 ms は過去の別計測として残し、今回の値と混同しない。

## 9. レビューで確かめる点・計画・要求への提案

判断はエージェントの案で、計画・要求の変更提案はない。空白を伴う量の後の単位を次の名前とする曖昧さは従来の分割規則を維持した結果であり、1 行 1 品を指示し続ける。同名・同詳細の番号は表示順の変化で変わるため、実際の操作感を H-23 で本人に確認する。3 組の計測は実行間の観察範囲を広げる設計上の回数であり、統計的な保証ではない。
