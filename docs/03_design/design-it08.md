# 設計書（反復 8）: 貼り付けと食材一覧の改善

- 文書 ID: DES-IT08
- 版: 0.1（下書き）
- 作成日: 2026-11-24

## 1. 範囲と既存設計との関係

IT08-PLAN 3.1 と SRS v0.10 を対象に、DES-RCP-02〜08、DES-BAL-05、DES-UI-40・49・51 を補足する。以下の具体的な判断はエージェントの案であり、本人の承認を意味しない。既存の直接一致・言い換え、登録前確認、保存形式、判定式と最低品数は変えない。貼り付けは従来どおり端末内で処理する。

## 2. 改行のない貼り付け（DES-RCP-09）

### 2.1 分割

元の物理行を CRLF または LF で分け、1 始まりの物理行番号を割り当てる。NFKC 正規化後、前後の空白と従来の行頭記号を除く。元の 200 文字制限は分割前の物理行に適用し、超過時は従来どおり元行全体を登録しない物にする。長い入力による正規表現の後戻りを避ける。

分割は、空白を含めて全体を覆う **2 組以上**の `名前,量` が、組の間の 1 個以上の半角または全角空白・タブで区切られていると一意に認識できる場合だけ行う。NFKC 後のコンマを区切りとし、名前は空でなく、量は 3 章の符号付き数値・分数と任意の既存単位、g・kg・ml の全体に一致すること。各名前には空白を含めてよい。量の直後から次の名前の前までの空白だけを組の境界とする。桁区切りのコンマは従来の規則で扱い、量の中のコンマを組の境界にしない。候補の境界が複数ある、途中に余りがある、または 1 組しかない場合は分割せず、従来の 1 行の解析へ渡す。カタログへの一致の有無で分割位置を変えない。

例えば `豚肉,1 鶏卵,1` は 2 組、`豚肉 300g` と `ロース ハム,1` は従来どおり 1 行。`豚肉,1 たまご＆チキンサラダ,1` は後者が未一致でも別々に扱う。分割後の各候補・登録しない物は同じ元の物理行番号を持ち、元の順で表示する。未一致の表示テキストはその組の原文とし、分割しなかった行は従来どおり元行とする。重複した食材は勝手に合算しない。

空白だけで分ける案は `豚肉 300g` や商品名の空白を壊すため採らない。コンマのない複数組の推測や曖昧な部分だけの救済はしない。

### 2.2 指示文

DES-RCP-02 の形式の指示を「必ず食材 1 品ごとに改行し、1 行に 1 品だけを『食材名,量』の形で書いてください。複数の品を空白でつないで 1 行に書かないでください。」に置き換え、既存の重量・個数・小数の指示は維持する。コピー方法で改行が失われる場合もあるため、指示強化だけには依存しない。

## 3. 読み取りの残り（DES-RCP-10）

- `1/2個` のように既存の個数単位、g・kg・ml を分数の後に付けられる。分母 0、非有限値は既存の不正量と同様に個数 1・要確認とし、分数は丸めの有無にかかわらず要確認とする。既存の個数の 0.5 刻み・上限、重さの整数 g・範囲と要確認の規則を適用する。
- 行頭の `•` を既存の `-`・`*`・`・` と同様に除く。負号を箇条書きと誤認しないよう、量部分の符号は除かない。
- ml は対象を食材名で限定せず、貼り付けで明示された体積だけを **1 ml ≒ 1 g の概算**として購入時重量に換算し、整数 g に丸め、範囲制限も既存の重量と同じにする。密度は食品で異なるため常に要確認とし、確認画面で「ml を 1 ml ≒ 1 g の概算で換算しました。重さを確認してください」と示す。保存は既存の g の重量で、ml の表示単位や食品別密度は追加しない。この係数は外部資料による実測値ではなくエージェントの簡易な仮定で、本人の査閲を要する。
- 明示的な負の量（`-1`、`-1/2個`、`-200ml` など）は一致する食材でも候補にせず、その組を登録しない物に回す。負号を落として正の量にしない。0 とその他の不正値は既存の要確認の扱いを維持する。

食品ごとの密度表は根拠と対象の査閲が必要で今回作らない。負の量を 1 にして候補にする案は値引き行の誤登録を招くため採らない。複数組からも同じ規則で負の量を認識する。

## 4. 少ない登録の案内（DES-BAL-08）

`analyzeBasket` が判定に使う `active` の行数を judged 結果にも渡す。正の量かつエネルギー値が null でない登録行を数え、同名でも別行なら別に数える。設定で自動追加する主食は含めない。これは既存の最低 3 品目の数え方と揃えるためで、食品の種類数ではない。判定できた場合に限り、3 または 4 行なら案内し、5 行以上と未判定では出さない。境目 5 は E-146 の例を採用したエージェントの判断であり、根拠ある栄養学上の閾値ではない。

ホームと前の買い物の `BalancePanel` の判定見出し直下に「登録した食材が少ないため、判定は登録した食材と設定した主食に基づく目安です。」と表示する。主食なしの場合は「登録した食材に基づく目安です。」とする。栄養詳細には追加しない。判定の入口で伝え、対象外の判定画面の改修を広げないため。常時表示や主食を品数に加える案は、少ない登録への注意を曖昧にするため採らない。多品数でも肉・卵に偏る例には案内が出ないことを H-20 の結果と分けて記録する。

## 5. ホームの食材行（DES-UI-52）

閉じた行は `［食材名（開閉）］ ［−］ ［量］ ［＋］` の横 1 行とする。名前領域は独立したボタンで、押すと行内の詳細を開閉する。個数は従来どおり 0.5 刻み、最小・最大では該当ボタンを無効にする。重さの場合は量と単位を表示し、増減ボタンは表示せず、編集は詳細に置く。行全体をボタンにせず、増減操作が開閉を起こさないようにする。

開いた詳細に食品の詳細名、目安重量、個・g・kg の切り替え、重さ入力とエラー、削除を置く。既存の換算、重さ確定、無効入力、切り替え後の焦点（DES-UI-51）と削除取り消しを保つ。詳細を閉じる際に未確定の重さを検証・確定し、無効なら開いたまま入力欄へ焦点を戻す。削除後は既存の取り消し通知へ焦点を移す。開閉状態は画面内の一時状態で保存しない。

名前ボタンに食材名と「詳細を開く／閉じる」の読み上げ名、`aria-expanded` と対応する領域の `aria-controls` を付け、Tab・Enter・Space で操作する。増減・単位・削除にも食材名を含む既存の名前を保つ。閉じた領域はフォーカス対象にしない。360 CSS px で名前領域を縮めて省略表示し、完全な名前は読み上げ名と開いた詳細で確認できるようにする。各操作領域は 44 × 44 CSS px 以上、横スクロールなし。長い量・名前を含む実寸で確認する。

同じ `ItemRow` を使う前の買い物の詳細にも同じ操作を適用し、その買い物だけを変更する。登録画面は既に食材名の 1 押し登録があり、ホームから 3 タップ以内を満たすため変更しない。使い切りは追加しない（E-149）。行の `memo` と画面外描画の最適化を維持し、推定高さを新しい行の実寸に合わせて見直す。CPU 4 倍・100 行で登録、増減、削除から判定更新まで NFR-03 の 100 ms を再計測する。

## 6. 共通の検証と互換性

core は純粋関数のまま表駆動単体テストを追加し、網羅率・型・lint を維持する。保存形式は変えず既存データを読む。画面は mobile / desktop、360 px、閉じた状態と開いた状態で寸法・axe の重大違反 0・キーボード・読み上げ名を検査する。既存の登録・履歴・重さ・削除・性能 E2E も維持し、操作位置の変化に合わせる。CI の性能時間超過は既存方針どおり記録のみ、計測不能・機能不整合は失敗とする。

## 9. レビューで確かめる点・計画・要求への提案

分割の一意性と長さ制限、負数の登録しない物への振り分け、ml の一律概算と確認表示、3・4 行の案内、主食を含む文言、行の開閉と履歴への適用をレビューする。ml の係数は食品ごとの正確な密度ではなく、本人の査閲が必要。設計上の判断は本人の指示や承認ではない。計画・要求への変更提案はない。
