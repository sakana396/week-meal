# ADR-0006: レシートの貼り付けの方式

- 状態: 設計案（DES-IT05 のレビューで採用を判断する。方式の大枠は本人の決定、細部はエージェントの判断）
- 日付: 2026-11-02
- 根拠: SRS-001 FR-RCP-01〜03、NFR-14、IT05-PLAN P-02, P-04〜P-06、E-29、E-84、E-97、E-98、DES-IT05 DES-RCP-01〜05

## 背景

本人は、買った食材を 1 つずつ押す代わりに、レシートから登録したい（E-29、「記入メンドーだ／レシートからいけないか」2026-11-02）。アプリはサーバーのない静的なページで（ADR-0001）、登録したデータを外部に送らない（NFR-14）。

## 決定

1. **画像はアプリで読まない**。本人が外部の AI のウェブページにレシートの画像を渡してテキストを作り、そのテキストをアプリに貼る（E-84。本人の決定）
2. アプリは、外部の AI に渡す**指示文**を作ってコピーできるようにする。指示文には、登録の一覧の食材名（2026-11-02 時点で 186 件）と、1 行に 1 品の `食材名,量` の答えの形を入れる。食べ物でない物は書かず（E-98）、一覧に当てはまらない食べ物は商品名のまま書くよう頼む（DES-RCP-02。指示文に一覧を入れること、一覧にない食べ物の書き方はエージェントの提案）
3. 貼ったテキストは、`src/core` の純粋な関数で行ごとに読み、食材名を一覧と**完全一致**（両方に同じ正規化をかけて比べる）で当てる。当たらない行は登録せず、名前と件数を見せる（DES-RCP-03, 04、E-98）
4. 確かめてから、開いている買い物へ 1 回の操作で登録する（DES-RCP-05、E-97）

## 理由

- 外部に何も送らないので、NFR-14 と静的サイトの方針（ADR-0001）を変えずに済む。API キーも中継のサーバーも要らない
- 名前の当て方を AI に任せるので、レシートの略した商品名（「ﾄﾘﾑﾈ」など）の辞書をアプリで持たずに済む。アプリ側は完全一致だけで済み、表駆動の単体テストで確かめやすい
- 確認の一覧を挟むので、AI の読み違いを登録の前に直せる

## 検討した代替案

| 案 | 採用しなかった理由 |
|---|---|
| スマートフォンの文字認識で写した生の文字を貼り、アプリが商品名を当てる | 略した商品名を当てる辞書とあいまい一致が要り、当たり外れが大きい。本人は選ばなかった（E-84） |
| ブラウザの中で文字を認識する（Tesseract.js など） | 認識のデータが数 MB あり、日本語のレシートの読み違いが多い見込み |
| アプリから AI の API に画像を送る | NFR-14 を変える必要があり、API キーと中継のサーバーが要る。本人は「3 のような感じ」としつつ、外部のウェブページで作ったテキストを貼る形を選んだ（E-84） |
| あいまい一致で当てる | 誤って別の食材に当てると、確認で気づきにくい。指示文で一覧の名前を使うよう頼むので、完全一致で足りると判断した |

## 影響

- 外部の AI が一覧の名前を守らないと、「一覧にない物」が増える。確認の一覧で件数と元の文字列を見せ、本人が登録画面で登録し直せる
- 指示文は食品データの一覧が変わると変わる。指示文は毎回アプリが作るので、本人が古い指示文を使い続けない限り問題にならない
- 外部の AI のサービスの選び方、使い方、レシートの画像の扱いは本人に任せる。アプリはそれらに依存しない

## 追記（2026-11-03、IT06）: 言い換えの表

- 根拠: SRS-001 FR-RCP-04、IT06-PLAN P-05、E-102、E-116、DES-IT06 DES-RCP-06, 07
- 状態: 採用・実装済み（DES-IT06 の設計レビュー REV-066・PR #130 で採用し、Issue #131 で実装。言い換えの表を持ち完全一致で当てることは本人の決定、細部はエージェントの判断）

### 背景

外部の AI は、指示文で頼んでも一覧と違う表記（「生椎茸」など）で答えることがある（E-102）。決定 3 の完全一致だけでは、その行が「一覧にない物」になり、本人が登録画面で登録し直す必要があった。

### 決定

決定 3 を変えず、**言い換えの表**（`src/data/receiptAliases.ts`）を足す。一覧の名前に完全一致しない行だけを、表のキーに完全一致で当て、値の食材名にする（1 段だけ）。表に載せるのは、漢字・ひらがな・カタカナの違い、「生」などの状態の付け足し、同じ食材を指す一般的な別名に限る（DES-RCP-06）。あいまい一致とひらがな・カタカナの自動のそろえはしない（E-116）。

### 理由の書き直し

上の「理由」の「レシートの略した商品名の辞書をアプリで持たずに済む」は、略した商品名（「ﾄﾘﾑﾈ」など）を当てる辞書については今も成り立つ。言い換えの表は、完全一致の範囲で当たる表記を増やすもので、略した商品名を推測して当てる辞書ではない。表の値が一覧の食材名にあること、キーが一覧の食材名と重ならないことを単体テストで確かめる（DES-RCP-06。NFR-11 の趣旨）ので、表駆動の単体テストで確かめやすいことも変わらない。

### 影響

- 表にない表記は今までどおり「一覧にない物」になる。本人の利用で出た表記を、出どころを書いて表に足していく
- 言い換えで当てた行は、確認の一覧に元の表記を見せる（DES-RCP-07）ので、当て違いに気づける
- 食材名を分けたので（DES-CAT-07）、指示文の食材名の一覧が 2 件増える（決定 2 の 186 件は 2026-11-02 時点の件数）
