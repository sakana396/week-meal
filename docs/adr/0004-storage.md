# ADR-0004: 登録データと設定の保存方式

- 状態: 採用（自動マージの条件 4 により、エージェントの判断で採用。REV-009。本人には IT02 の振り返りで提示する）
- 日付: 2026-10-14
- 根拠: SRS-001 FR-SYS-01, 02、NFR-12, 13, 14、TBD-13（v0.3 で本人が localStorage に決定。REV-013）、IT02-PLAN P-03

## 背景

- 登録した食材と設定を、ブラウザを閉じても残す必要がある（FR-SYS-01）
- ログインなしで使え（FR-SYS-02）、データを外部に送らない（NFR-14）
- 保存データが壊れていても落ちず（NFR-12）、旧い版を読める（NFR-13）

## 決定

- 保存先はブラウザの **localStorage**。キーは `weekmeal:state`
- 中身は版番号つきの JSON

```json
{
  "version": 1,
  "items": [
    { "id": "…", "foodId": "06212", "displayName": "にんじん", "count": 2, "usedUp": false }
  ],
  "manualFoods": [ /* 手入力の食品（FoodItem と同じ形） */ ],
  "profile": { "sex": "unspecified", "ageGroup": "30-49", "staple": "rice", "portion": "medium" }
}
```

- 登録した食材は **食品番号（foodId）** で持ち、成分値は保存しない。読み込み時に食品データから引く。手入力の食品だけは成分値ごと `manualFoods` に持つ
- 読み込み（`parseStoredState`）と書き出し（`serializeState`）は `src/core/storage.ts` の純粋な関数にし、localStorage を触るのは画面側の小さな部品だけにする（NFR-08）
- 読み込みで次の場合は、**初期状態で起動し、その旨を画面に出す**（NFR-12）
  - JSON として読めない、形が違う
  - 版番号が今より新しい
- 1 件ずつ形を確かめ、食品データにない食品番号の食材や、値がおかしい食材（個数が 0.5 刻みでないなど）は捨てて、残りを読み込む。捨てた件数を画面に出す。検査の細かい規則は DES-IT02 の DES-STO-03〜06
- 全体が読めなかったとき（版が新しすぎるときを含む）は、書き出す前に元の文字列を `weekmeal:state:backup` に退避する。新しい版のデータを古いアプリが上書きして消さないため
- 検査した項目だけで新しいオブジェクトを作り、保存データの余計なキーを状態に持ち込まない
- 版番号が旧いときは、移行の関数で今の形に直す（NFR-13）。版 1 が最初の版なので、今は移行の関数はない

## 理由

- **localStorage**: 同期的で扱いやすく、データ量（数十〜数百件）に十分。IndexedDB は今の規模には大きすぎる
- **食品番号で持つ**: 保存データが小さく、食品データの表示名や目安重量を直したときにも、保存データを直さずに反映される
- **読み込みを純粋な関数にする**: 壊れたデータの扱いを単体テストで確かめられる

## 検討した代替案

| 案 | 採用しなかった理由 |
|---|---|
| IndexedDB | 非同期で扱いが重い。データ量が少ない |
| 成分値ごと保存する | 保存データが大きくなる。食品データを直しても古い値が残る |
| サーバーに保存する | ログインが要り、外部送信になる（FR-SYS-02、NFR-14） |

## 影響

- 端末やブラウザをまたいだ同期はできない（SRS 7 章の将来の要求）
- 食品データから食品を外すと、その食品を登録していた保存データは読み込み時に捨てられる。捨てた件数を出して知らせる

## IT03 の補足（2026-10-24、Issue #52。採用）

- 全体が読めなかった保存データを退避できなければ、**その起動中は保存を止める**。初期状態で操作は続けられるが、元の `weekmeal:state` を初期状態や操作後の値で上書きしない。保存・退避できなかった旨を画面で知らせる。`loadAppState` は `available = false` を返し、`App` は保存処理を呼ばない（DES-IT03 DES-STO-09）。これは IT02 からの持ち越しで、現行実装に合わせた明文化。
- IT03 では保存を版 2 にする。`manualFoods` は登録行から参照されなくなっても、再登録用に覚えた食品として残す。任意の `sourceFoodId` は下書き元の来歴で、成分値が原典と同じであることを保証しない。版 1 の手入力も移行して覚える。移行と検査の詳細は DES-IT03 DES-STO-08。
- 削除の取り消し用の一時状態 `pendingRemoval` は保存対象に含めない。保存対象の `AppState` に追加せず、`BasketSessionState` で包んで管理する（DES-BSK-09）。上の JSON は IT02 の版 1 の例として残す。版 2 でも保存先のキーと、同梱食品を番号で引く方針は変わらない。
