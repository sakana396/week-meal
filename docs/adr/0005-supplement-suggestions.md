# ADR-0005: 補う候補の選び方

- 状態: 採用（Issue #52、PR #53。レビューの指摘を受けたエージェントの設計判断で、AGENTS.md の自動マージの条件 4 により採用する。本人の決定（IT03-PLAN P-02 など）は変更しない。REV-027）
- 日付: 2026-10-25
- 根拠: SRS-001 FR-BAL-06, 07、FR-NUT-05, 06、NFR-03, 08、QA-08、IT03-PLAN P-02, 06、DES-IT03 DES-SUG-01〜03、DES-UI-42、DES-PER-01

## 背景

ホームから登録できる補う候補を 3 件まで出す。現在不足しているキーだけを評価すると、候補によって新しく生じる不足を見落とす。また候補ごとの全行再集計は、判定更新まで 100 ms の予算を圧迫する。候補の評価は実際の判定と同じ規則を使い、仮定を登録・保存へ混ぜない必要がある。

## 決定

- 登録できるよくある食材の代表食品を、独立に 1 単位追加する。通常登録と同じ個数上限・使い切った行の再利用を適用する。手入力は候補集合に入れない。
- 下限規則と PFC の全キーの、判定境界までの不足量の減少を等重みで合計する。下限規則は `max(0, 0.7 − sufficiency)`、PFC は `max(0, 1 − pfcPct / 下限)`。新たな不足と既存不足の悪化も負の寄与になる。塩分は不足評価から除き、上限規則の `lowerTargetRatio` は null とする。
- 前後とも判定可能なキーだけを合計し、現在判定できるキーの判定可能性・カバー率を下げる候補は除く。候補自身に改善する成分のデータがあることを必要とし、unknown を 0 としない。
- 小数第 6 位で丸めた総改善が正のものを、新しい過剰の有無（なしが先）→新しい不足の件数→既存過剰の悪化件数→改善量の降順→よくある順→食品番号順で比較する。既存過剰の悪化は塩分の上限超過比と PFC の上限超過比の増加で判定する。正確な定義は DES-SUG-03 に置く。
- 新しい不足・過剰や既存過剰の悪化がある候補を禁止はせず、順位と注意文で扱う。改善しない候補で 3 件を埋めない。
- 元の合計・カバーするエネルギー・登録一致の索引・基準値を 1 回求め、各候補では増分と追加後の主食の寄与を加えて再判定する。詳細充足率等は省く。全行再計算との同値性を単体テストにする。
- UI では実際の判定の描画機会の後に候補を計算し、状態の revision が古い結果を捨てる。候補までの時間は別計測とし、候補の仮定を実際の analysis・登録・保存へ混ぜない。

## 理由

不足量を比で測れば単位の違いを避けられ、等重みなら根拠のない栄養学的な重みを作らずに済む。総量だけでは少数の改善と引き換えに別の不足を増やすことがあるため、新しい不足の件数も優先順位で比較する。既存の塩分などの過剰をさらに増す候補も後ろに置く。新しい過剰の有無を最優先とする FR-BAL-07 と P-06 は維持する。

差分計算は主食と欠損の規則を保ちながら行数ぶんの繰り返しを削減できる。描画後の実行も組み合わせ、判定の応答と候補の負荷を分ける。100 行・80 候補・4 倍 slowdown で差分準備と全候補計算 50 ms 以内を設計上の予算とする。判定描画後から候補の反映までは 100 ms を目安とする。見積もり・測定条件・CI の記録と実機相当条件の合否の区別は DES-PER-01 に置く。達成済みの数値ではない。

## 検討した代替案

| 案 | 採用しなかった理由 |
| --- | --- |
| 現在の不足だけを合計する | PFC の変化や成分の希釈で生じる新しい不足を減点できない |
| 不足の総改善量だけで並べる | 新しい不足や既存過剰の悪化を伴う候補が先頭になりうる |
| 栄養素に重みを付ける | 重みの栄養学的な根拠がなく、買い物での妥当性も未検証 |
| 候補ごとに `analyzeBasket` で全行を再計算する | 100 行・80 候補での反復集計と詳細用の計算が性能予算を圧迫する |
| 計算の遅延だけで対応する | 判定を先に描画できても、長い処理による後続操作への影響が残る |

## 影響と確認

順位は候補の個数、登録状態、主食・属性で変わる。栄養学的な最適化や医療上の助言ではない。TC-FR-BAL-07-01〜08、TC-FR-NUT-06-04 で式・並び・差分の同値性・仮定の分離を確かめる。買ってもよい候補になっているかは H-08 の本人の感想として振り返りに記録し、本人の決定や判定境界を無断で変えない。
