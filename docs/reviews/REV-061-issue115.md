## 確かめられたこと

- 登録画面の「レシートから登録」から `#/receipt?shopping=<id>` へ移る。ID がなければ最新の買い物に補い、不明・削除済みの ID は履歴へ移して知らせる。買い物が 0 件なら登録のときに今日の買い物を作る
- 指示文は receiptPrompt で作り、Clipboard API が使えないときは全体を選んだ読み取り専用の欄と「長押ししてコピー」を示す
- 名前は normalizeSearchText の完全一致で、一覧の食材が先。単位は unitWeightFor で引く（REV-059）
- 一括登録は UI が作る ID で registerMany を 1 回 dispatch し、通知は設計の文言（0 件の項は省く）。取り消しはない。登録後は最新ならホーム、前の買い物なら履歴の詳細へ移る
- NFR-14: 貼ったテキストは state だけに持ち、保存も送信もしない。E2E で fetch・XHR と別オリジンへの要求がないことを監査している
- Claude Code の手元で、2388be8 の機能 E2E は 201 件成功・4 件失敗（下の再レビュー 1 回目の A）。36c1004 で receipt.spec の 16 件、その前に receipt.spec と accessibility.spec の 28 件が成功

## 指摘と対応

### 初回（コミット 63e814e）: 修正が必要

Claude Code の手元の E2E で 8 件が失敗した（一括登録後にホームへ移らない、食材名の欄の fill がタイムアウト、axe の scrollable-region-focusable）。原因は、初回登録後の買い物 ID の補完の effect がホームへの遷移を古い描画から上書きしていたこと、食材名の欄が datalist で combobox になるのに E2E が textbox を探していたこと、指示文の領域に焦点を当てられなかったこと。App.tsx の補完に今の hash との比較を足し、E2E の指定を直し、指示文の `<pre>` に tabIndex と名前を付けた。レビュアーは、App.tsx の条件がほかの経路（register・receipt の補完、未知の ID）を壊さないことを確かめた。
