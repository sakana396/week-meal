- 配信の job は main への push のときだけ、check・e2e の成功後に動く。この PR の CI では skipping だった。`pages: write`・`id-token: write` は配信の job だけ。github-pages 環境の配信ブランチは main だけで、条件と合う
- `base: "/week-meal/"` で、dev の `/` は `/week-meal/` へ転送される。公開 URL で壊れる絶対パスはアプリにない
- Playwright の URL は `/week-meal/`（末尾の `/` あり）。既存 E2E の `goto("/` は残っていない（44 件をすべて相対にした）
- `pages.spec.ts` は、資産の読み込み、hash の移動、登録・設定・再読み込みでの保持、fetch / XHR がないことを確かめている
