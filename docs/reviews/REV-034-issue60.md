## レビューの前の経緯

- Claude Code の E2E で、候補を押したあと見出しにフォーカスが移らない不具合が見つかった。Codex が直したあとも、スマートフォン幅で 3 回に 1 回ほど失敗した。原因は、登録の通知が差し込まれてクリックの位置がリストの外にずれ、既定動作の抑制をすり抜けることだった。固定中は候補欄全体で既定動作を抑えるようにし、TC-FR-BAL-06-08 を 10 回繰り返して 60 件すべて成功した

## 確かめられたこと

- 候補欄は判定の直後にあり、押すと既存の `register` を 1 回だけ dispatch して、ホームに留まって通知する（P-02）
- 候補は描画の後に予約して計算し、後始末で予約を取り消す。古い revision の結果は捨てる（ADR-0005）
- 候補の仮定は表示側だけで計算し、実際の判定と保存に混ぜない（FR-NUT-06。E2E で確かめた）
- 固定中だけ既定動作を抑え、キーボードの操作は影響を受けない。候補欄にボタン以外の操作できるものはない
- effect の依存とアンマウント時の後始末に問題はない
- 検証コマンド 5 つと E2E（83 件成功、TC-FR-BAL-06-08 の 5 回の繰り返しで 30 件成功）が成功
