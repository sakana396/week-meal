# 反復 5 計画書: レシートの貼り付けと重さでの登録

- 文書 ID: IT05-PLAN
- 版: 0.1（本人の指示で作成。範囲と主な決定は本人が決めた。E-84、E-95〜E-101。要求の文と優先度、要求 ID への当てはめはエージェントの書き起こし。REV-054）
- 作成日: 2026-11-02
- 期間の目安: 1〜2 週間

## 1. 目的

IT04 の画面を本人が使った感想（E-86〜E-94）を受けて、登録の手間と量の分かりにくさを減らす。

1. レシートの食材を、本人が外部の AI のウェブページで作ったテキストとして貼り付け、確かめてから一括で登録できるようにする（E-84）。アプリは画像もテキストも外部に送らない（NFR-14）
2. 個数の分からない食材（冷凍の野菜、大容量のパック、もらい物、箱で買う玉ねぎなど）を、重さ（g・kg）で登録できるようにする（E-88〜E-90、E-100）。個数で登録するときは、1 単位の目安の重さを見せて、単位の基準を分かりやすくする（E-87）
3. IT04 の持ち越し（IT04-RETRO 4 章）を直す。NFR-03 は、CPU 4 倍の模擬（E-78）で 100 ms 以内になるよう、日付の変更の再計算を速くする（E-83）

## 4. 作らないもの

- アプリの中でレシートの画像を読むこと（ブラウザの文字認識、外部の AI の API への送信）。画像を読むのは本人が開く外部の AI のウェブページに任せる（E-84）
- 一覧にない物を、貼り付けから手入力の食材として登録すること（E-98。手入力は今の登録画面で行う）
- レシートの日付から新しい買い物を作ること（E-97。入れ先は今開いている買い物）
- 特定の AI のサービスとの連携、指示文の AI ごとの作り分け
- 炭水化物の不足の判定の調査（E-93 の違和感。E-95 で IT05 に入れなかった。IT04-RETRO 4 章に残す）
- 判定の規則・計算の変更、目安の重さのデータの見直し（表示の追加だけ）
- 個数・g・kg 以外の単位（ml など）での入力
- SRS 7 章のほかの将来の要求（外食の記録、端末間の同期など）

## 6. 完了条件

- 3.1 の要求が設計どおりに実装され、単体テストと E2E テストが通っている
- 貼り付けのテキストの読み取りと、食材名・量への当てはめは `src/core` の純粋な関数にし、表駆動の単体テストで確かめている（NFR-08）。崩れた形のテキストでも例外を投げず、読めない行として返す
- 貼ったテキストを外部に送っていないことを E2E で確かめている（NFR-14）
- 旧い版の保存データを読み込むテストが通り、食材のデータが失われない
- `src/core` の命令網羅率 80% 以上を保っている
- axe の検査で、追加・変更した画面に重大な違反がない（NFR-06）
- NFR-03 を CPU 4 倍の模擬で測り、100 行の日付の変更を含めて 100 ms 以内である
- main へのマージで公開した URL に配信され、そこで貼り付けから登録まで動く
- トレーサビリティマトリクスで、IT05 で追加・変更した M・S の要求が設計要素とテストケースに対応付いている（QA-05）
- 3.2 の持ち越しが直っているか、直さない理由が振り返りに書かれている
- 仮説の検証結果が振り返りに記録されている（本人の回答はエージェントが質問で聞く）
