## 2. 仮説の検証結果

### H-19 改行のない組や選んだ書き方を読むと、貼り付け後の手直しが減る（本人の試用で問題なし）

本人が公開版で、ChatGPT のコピーボタンで改行のない答えを貼って登録できた（E-151）。IT07 で 1 件も登録できなかった方法（E-131〜E-133）で登録できたことは確かめた。貼ったテキスト、品数、手直しした行の件数は聞いておらず、手直しが減った量は数えていない。分数＋単位・「•」・ml・負の数を含む答えだったかも分からない。`豚肉, 1 鶏卵, 1` のようにコンマの後に空白があると分けない限界は残る（DES-IT08 9 章）。

### H-20 少ない登録の案内で、判定が登録した食材に基づくことが伝わる（本人の試用で問題なし）

本人が公開版で案内を確かめ、問題なしと答えた（E-151）。試した品数と主食の設定は聞いていない。境目 5 行と文言は、本人が「このままでよい」と答えた（E-152）。品数が多くても肉・卵の割合が大きい登録では案内が出ず、IT07 の例の計算で炭水化物が不足になった登録（carbohydrate-investigation.md 3.2 の例 5）は案内の対象外のまま。

### H-21 ホームの食材を 1 行に詰めると、見渡しやすく操作しやすくなる（見やすくなった）

本人は公開版で「見やすくなった」と答えた（E-150）。名前を押して詳細を開く操作の分かりやすさは個別には聞いていない。レビューでは、名前のボタンが見た目から押せると分かりにくいこと、開いた同名の 2 行で削除などの読み上げ名が同じになることが観点として挙がった（REV-083）。

  - 性能の比較で、計測のぶれの大きさを示し、数値で言える範囲に結論を限った（REV-083）。
  - A・C・D を並行して実装し、計画から実装・配信までを 1 日で進めた。
- 困ったこと
  - 並行した E2E がポート 4173 でぶつかった。Codex に localhost を許して E2E を任せた D と、メインが実行した A・C の E2E の時間が重なり、D の作業が止まったり、A の E2E で 2 件が失敗したりした（作成者の見立て。失敗の原因は確かめていない）。以後は、Codex が E2E を使う間はメインが E2E を実行しないようにした。
  - Codex が並行して単体テストなどを動かしている間に性能を測ったため、値が負荷の影響を受けた。性能は、ほかの作業を止めて測り直した（performance-measurement-it08.md）。
  - 実装の PR の CI では成功した E2E が、main へのマージ後の CI で時々失敗し、配信が止まった。保存の予約（DES-UI-50）と画面外の行の描画の後回し（DES-PER-07）を待たずに読むテストが原因で、#167 で直した（REV-085）。
  - 配信の手順が GitHub の成果物の取得で一度失敗し、再実行が必要だった。原因は確かめていない。
  - メインが E2E の結果の行だけを見て、失敗を見落としかけた（A の E2E の「20 件成功」。REV-081 R-2 で指摘され、再実行で 22 件成功を確かめた）。
  - 計画・設計・実装の各段階で、レビューの指摘を直し再レビューする往復が多く、PR ごとに 2〜3 回のレビューが要った。
