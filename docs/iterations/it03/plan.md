## 1. 目的

IT02 の画面を本人が使った感想（E-46〜E-49）を受けて、偏りの「程度」がホームで分かり、不足を補う食材をその場で登録できるようにする。あわせて、削除の取り消しと手入力の改善で操作の失敗や手間を減らし、性能とアクセシビリティを測れる状態にする。IT02 から持ち越した文書とテストの不備を片づける。

## 3. 対象の要求

### 3.1 新しく作るもの

| 区分 | 要求 | 内容 |
|---|---|---|
| 提案 | FR-BAL-06（S）、FR-BAL-07（C） | 不足している栄養素を補う食材の候補を、ホームに出す。押すとその場で登録する（E-53）。候補は、加えたときに不足が減り、新しい過剰を生まないものを優先する |
| 判定の見せ方 | FR-UI-06（M、表示の改善）、NFR-07 | ホームの「不足」を、充足率に応じて赤（0%）→ 橙 → 黄（100%）の色で見せる。過剰は不足と区別できる別の色（紫など）。「不足」「過剰」の文字は残す（E-48、E-49。DES-UI-01 の変更） |
| 登録 | FR-ING-14（S、SRS v0.4 で追加） | 削除を 1 回の操作で取り消せる（E-55） |
| 手入力 | FR-ING-08（S、入力のしやすさの改善）、FR-ING-15（S、v0.4 で追加）、FR-ING-16（C、v0.4 で追加） | 手入力した食材を覚えて次から一覧で 1 回押すだけで登録できる。見つからなかった検索語を手入力の名前に引き継ぐ。成分の欄は普段たたむ。食品データの似た食品の成分を下書きにできる（E-56） |
| 性能 | NFR-03（S）、NFR-04（C） | 登録・個数の変更・使い切ったから判定の更新までの時間を確かめる。Lighthouse のモバイルの Performance スコアを反復の終わりに記録する（QA-04） |
| アクセシビリティ | NFR-06（C） | axe を E2E に組み込み、重大な違反を検出する |

FR-ING-16 と CST-04（架空の成分値を作らない）の関係: 下書きに入るのは食品データにある実在の食品の成分値で、どの食品から写したかを利用者が選び、登録の前に直せる。アプリが成分値を作り出すのではないので CST-04 に反しない。どの食品を写したかを登録した食材に残すかは設計で決める。

## 4. 作らないもの

- 公開（配信先を決めて配信すること）。ビルドできる状態は保つ（E-54）
- 判定の規則・計算の変更（不足 70% 未満・過剰 130% 超、14 種、主食の足し方）。補う候補は今の判定の結果を使って選ぶ
- 不足以外の栄養素（適正）の色分け。色を付けるのは不足と過剰だけ（E-49）
- 棚の規則の見直し（即席めん・冷めんなど）と、感度分析を棚ごとにまとめてずらすこと（IT01 からの持ち越し。IT04 以降で検討）
- レシート入力（FR-RCP-01、W）など SRS 7 章の将来の要求
- 手入力した食材の、覚えたものの一覧からの削除・編集の画面（覚えるだけにする。必要なら IT04 以降）
