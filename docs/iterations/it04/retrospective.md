過剰は上限超過比 0〜0.5 に応じて、薄い紫 `#d8b4fe` から濃い紫 `#a855f7` へ連続して変わる（DES-COL-03、PR #93）。黒文字とのコントラスト比は、紫の 256 段階すべてで 4.5:1 以上を単体テストで確かめた。

安全性の順位を保てる範囲で、直前と違う棚の候補を繰り上げる（DES-SUG-04、ADR-0005 の IT04 の改訂、PR #94）。出た候補の棚は本人の感想とともに記録する。

### H-13 公開した URL を本人のスマートフォンで開き、インストールなしで使えるか（本人の記入待ち）

## 6. 良かったこと・困ったこと

- 良かったこと
  - 保存データの版を上げる大きな変更（#84）を最初に単独で入れ、ほかの Issue をその上に積んだので、画面の Issue どうしの衝突は少なかった
  - 別のサブエージェントのレビューで、E2E では見つからない不具合が見つかった。例: 「戻る」で登録画面から抜け出せない（PR #92）、前の買い物の栄養詳細からの登録が最新の買い物に入る（PR #95）、配信の concurrency が PR の CI まで待たせる（PR #96）
  - 公開した URL の確認と Lighthouse を、開発者の PC から自動で行えた
- 困ったこと
  - Codex の初版（#84）で、main の単体テスト 565 件のうち 129 件の名前が消え、保存の試験がほぼ消えていた。Claude Code が件数を比べて気づき、戻させた。以後の依頼文に「既存のテストを消さない。件数の差と内訳を報告する」を足した
  - Codex のサンドボックスでは E2E を起動できないので、E2E の失敗は毎回 Claude Code が見つけて Codex に戻した（#85、#87、#88、#86）
  - テストの試料を直すとき、検査の強さが下がることがあった（#88 の候補の固定の試料。REV-046 #1）
  - Claude と Codex の利用枠が何度か上限に近づき、作業を止めた。2026-11-02 の深夜は、本人が会話で「2 時になったら自動で起動して」と指示したので、Claude Code のセッションの予約で 2:13 に自動で再開した
  - 性能の E2E を Lighthouse と同時に流してしまい、計測値が大きく出た。測り直した回も、記録した時刻がコミットの時刻と食い違い、レビューで裏付けを求められた（REV-049 #1）。計測は 1 つずつ、ほかのプロセスがないことを確かめ、開始・終了の時刻を控えて流す
