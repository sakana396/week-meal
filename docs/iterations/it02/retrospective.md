## 6. 良かったこと・困ったこと

- 良かったこと
  - 状態（basket reducer）と保存を `src/core` の純粋な関数にしたので、壊れた保存データ・新しすぎる版・容量不足などの異常を単体テストで網羅できた
  - E2E を入れたことで、目で見て気づきにくい表示の崩れ（食材一覧の行の高さ、PC 幅のサイドバーの sticky）が見つかった。レビュアーが修正を外してテストが失敗することを確かめ、崩れを検出できるテストになった
- 困ったこと
  - 画面の Issue を積み上げて並べたため、トレーサビリティとテスト仕様書の衝突の解消が続いた。行が古いまま残ることもあった
  - PR #41 はサブエージェントのレビューで承認されてからマージしたが、レビュー記録を `docs/reviews/` に残し忘れた（自動マージの条件 2 を満たしていなかった）。振り返りのレビューで見つかり、レビュアーの報告から REV-023 を書き起こした
  - E2E の最初の版は「実装済み」と書いた範囲が広すぎ、レビューで 15 件の指摘を受けた（保存の問題の 5 場面のうち 1 つしか確かめていない、など）
- エージェントの作業
  - 2026-10-15 から、本人の指示で実装を Codex、レビューとマージを Claude Code に分けた（AGENTS.md「エージェントの分担」、REV-021）。PR #40 の指摘 15 件を Codex が直し、別のサブエージェントの再レビューで承認された
