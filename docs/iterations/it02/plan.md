# 反復 2 計画書: 登録と判定の画面（MVP）

- 文書 ID: IT02-PLAN
- 版: 0.1（エージェントの判断で開始。本人は IT02 の振り返りで確認する）
- 作成日: 2026-10-14
- 期間の目安: 1〜2 週間

## 1. 目的

本人が実際の買い物で 1 週間使い続けられる最小の形（MVP、PLAN-001 2.1）を作る。買った食材を 1 タップで登録し、個数を直し、使い切った食材を外し、主食と属性を設定すると、ホームで偏りが分かる。データはブラウザを閉じても残る。

## 2. 確かめたい仮説

| ID | 仮説 | 確かめ方 |
|---|---|---|
| H-01 | 判定が実感と合う（IT01 から持ち越し） | 本人の実際の買い物 2〜3 回を登録し、振り返りに記録する |
| H-03 | 普段の買い物の 9 割以上が一覧から見つかる（IT01 から持ち越し） | 同上の品目のうち、一覧にあった割合を記録する |
| H-04 | 主食をエネルギー比で足す方式で、判定が自然になる（IT01 から持ち越し） | 設定画面で盛りを変え、判定の変化が自然かを記録する |
| H-05 | ホームから食材 1 件の登録が 3 タップ以内で終わる（NFR-02） | E2E テストでタップ数を数える |
| H-06 | 本人が 1 週間、記録をやめずに使い続けられる | 本人の感想を振り返りに記録する |

## 3. 対象の要求

| 区分 | 要求 ID | 反復 2 での扱い |
|---|---|---|
| 登録 | FR-ING-01〜04, 10, 11, 12, 13 | 既存の 1 タップ登録を新しい画面に移す。登録済みの一覧で個数の変更・使い切った・取り消し・削除 |
| 量 | FR-QTY-01, 04 | 個数を 0.5 刻みで増減 |
| 設定 | FR-STP-01, 02, 04, 05, FR-UI-09 | 設定画面。初期値で使い始められる |
| 表示 | FR-UI-01〜07 | 画面を作り直す（ホーム・食材登録・栄養詳細・設定・食品一覧） |
| 保存 | FR-SYS-01, 02 | localStorage に保存（ADR-0004） |
| 外部 IF | IF-01〜05 | 360px と 1280px で崩れない。タップできる要素は 44px 以上 |
| 非機能 | NFR-01, 02, 07, 12, 13, 14 | 使いやすさ、3 タップ、色以外の表示、壊れた保存データ、版、外部送信なし |
| 品質保証 | QA-03 | Playwright の E2E（スマートフォン幅と PC 幅） |

詳細モード（FR-ING-07）と食品一覧（FR-UI-08）は、既存の動作を新しい画面に移すだけにする。

## 7. 開始前の決定事項（エージェントの判断。振り返りで本人が確認）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| P-01 | 画面の切り替え | ルーティングのライブラリを入れず、URL のハッシュ（`#/home` など）で画面を切り替える | スマートフォンのブラウザの「戻る」で前の画面に戻れる。依存を増やさない |
| P-02 | 状態の管理 | React の `useReducer` と、`src/core` に置く純粋な reducer を使う。外部のライブラリは入れない | 登録・個数・使い切ったの規則を単体テストで確かめられる（NFR-08） |
| P-03 | 保存 | localStorage に版番号つきの JSON で保存する（ADR-0004） | TBD-13 の仮置きどおり。サーバーを持たない（NFR-14） |
| P-04 | 同じ食材をもう一度押したとき | 新しい行を作らず、その食材の個数を 1 増やす（使い切ったものなら、使い切ったを外して個数を 1 にする） | 一覧が同じ食材で埋まらない。1 タップの登録で個数も増やせる |
| P-05 | E2E | Playwright の Chromium で、360×740 と 1280×800 の 2 つの画面幅を試す。CI でも実行する | QA-03、IF-03・04 |
| P-06 | 画面の並び | スマートフォンは画面下のタブ（ホーム・登録・詳細・設定）、PC は左のサイドバー。食品一覧は設定画面から開く | 主な操作を 1 タップで開ける（FR-UI-03） |
