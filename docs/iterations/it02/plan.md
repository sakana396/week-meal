# 反復 2 計画書: 登録と判定の画面（MVP）

- 文書 ID: IT02-PLAN
- 版: 0.2（本人の指示「次のサイクルへ進んで」で開始。開始前の決定のうち要求にかかわるものは本人が決定。REV-010、REV-013）
- 作成日: 2026-10-14
- 期間の目安: 1〜2 週間

## 1. 目的

本人が実際の買い物で 1 週間使い続けられる最小の形（MVP、PLAN-001 2.1）を作る。買った食材を 1 タップで登録し、個数を直し、使い切った食材を外し、主食と属性を設定すると、ホームで偏りが分かる。データはブラウザを閉じても残る。

## 2. 確かめたい仮説

| ID | 仮説 | 確かめ方 |
|---|---|---|
| H-01 | 判定が実感と合う（IT01 から持ち越し） | 本人の実際の買い物 2〜3 回を登録し、振り返りに記録する |
| H-03 | 普段の買い物の 9 割以上が一覧から見つかる（IT01 から持ち越し） | 同上の品目のうち、一覧にあった割合を記録する |
| H-04 | 主食をエネルギー比で足す方式で、判定が自然になる（IT01 から持ち越し） | 設定画面で盛りを変え、判定の変化が自然かを記録する |
| H-05 | ホームから食材 1 件の登録が 3 タップ以内で終わる（NFR-02） | E2E テストでタップ数を数える |
| H-06 | 本人が 1 週間、記録をやめずに使い続けられる | 本人の感想を振り返りに記録する |

### 3.2 IT02 で一緒に扱う S の要求と、その理由

PLAN-001 2.1 は「S・C の要求は MVP の後」としているが、次は M の要求と同じ画面・同じ仕組みで、分けるとかえって手間が増えるので IT02 で扱う。

| 要求 | 理由 |
|---|---|
| FR-ING-07（詳細モード）、FR-UI-04（モードの切り替え）、FR-UI-08（食品一覧） | 既存の画面にあり、新しい構成に移すだけ |
| FR-ING-12（使い切ったの取り消し）、FR-QTY-04（0.5 刻み） | 使い切った・個数の変更（M）と同じ操作の一部 |
| IF-04（PC 幅） | 画面の構成（タブとサイドバー）を決めるときに一緒に決める |
| NFR-13（保存データの版） | 保存の形式（M）を決めるときに版を入れておかないと、あとから入れられない |
| QA-03（E2E） | 画面の確認を自動化しないと、IT01 で手動確認にしたものが残る |
