## 1. 目的

IT05 の振り返り（IT05-RETRO）4 章の持ち越しのうち、本人が選んだ 3 つを扱う（E-111）。

1. レシートの貼り付けで、外部の AI が一覧と違う表記（例: 生椎茸）で答えても当てられるようにし、ミニトマトのように 1 単位の大きさが大きく違う食品で量がずれないようにする（E-102、E-113、E-115、E-116）
2. 補う候補で「炭水化物が足りない」と出るのが実感と合わない（E-93）原因を調べ、本人に報告する。直し方は本人が選ぶ（E-112）
3. IT05 で採用した設計の判断（IT05-RETRO 3 章の 2〜4）を設計書に書き、技術的な宿題（行の高さの推定値、画面外の行の `innerText`、CI の性能 E2E の不安定さ）を片付ける（E-111）

## 3. 対象の要求

### 3.1 新しく作るもの・変えるもの

SRS を v0.9 に上げる。要求の文と優先度 S はエージェントの書き起こし（REV-065）。

| 区分 | 要求 | 内容 |
|---|---|---|
| 言い換えの表 | FR-RCP-04（S、追加）、FR-RCP-01・03（S、変えない） | 貼ったテキストの食材名が一覧の名前と違っても、言い換えの表にある表記ならその食材に当てる。当て方は完全一致のままで、あいまい一致はしない（ADR-0006、E-116）。表に載せる表記（漢字・ひらがな・カタカナの違い、「生」などの付け足し）はエージェントが洗い出し、出典（どの利用例から足したか）をデータの近くに書く。表の置き場所と、指示文の一覧に言い換えを載せるかは設計書で決める |
| 分けた食材名 | FR-ING-06（S、文の変更）、FR-QTY-02・08（M・S、変えない） | ミニトマトを「トマト」から分け、単位をパックにした別の食材名にする。登録画面にも指示文の一覧にも出す（E-115）。ほかに分ける食品は、エージェントが「1 単位の大きさが大きく違い、別の単位で売られる物」を洗い出し、本人が選ぶ（8 章）。目安の重さは出典を書く（QA-09）。前から保存している「トマト」の行の扱いは設計書で決める（NFR-13） |
| 炭水化物の調査 | FR-BAL-02・06、FR-NUT-04、FR-STP-03（変えない） | 補う候補で炭水化物が不足と出る原因を調べる。候補は、主食の盛りの比率（TBD-14）、成分表の炭水化物の列の選び方、エネルギー比の範囲（50〜65%）の当て方、本人の主食の設定と実際の食べ方の違いなど。調べた結果と直し方の選択肢を記録し、本人に報告する（E-112）。判定の規則と主食の比率は、本人が直し方を選ぶまで変えない |
| 設計書の整理 | DES-UI-13 ほか（設計書のみ） | IT05-RETRO 3 章の 2〜4（「個」へ切り替えた後の焦点、保存の予約と最後の状態だけの保存、画面外の行の描画の後回し）を設計書に書く。DES-UI-13 の保存の約束の変更を含む。本人は E-110 で 4 項目の文を確かめている |
| 技術的な宿題 | NFR-03、NFR-06（変えない） | `contain-intrinsic-size: 180px` の根拠になる行の高さを 360 px と 1280 px の幅で測り、必要なら直す。画面外の行で `innerText` が空になる件の表示・操作への影響を調べる。CI の性能 E2E が 1 回失敗した件（`e2e/performance.spec.ts`）の待ち方と負荷を調べ、必要なら直す。NFR-03 は今の計測の条件で 100 ms 以内を保つ |

## 4. 作らないもの

- あいまい一致（似た名前を推定して当てること）。ADR-0006 の決定を変えない（E-116）
- AI の答えの量を推定で直すこと（例: トマトの量が大きすぎるときに自動で減らす）。ミニトマトなどは食材名を分けて扱う（E-115）
- 分数に単位が付く行（`はくさい,1/4株`）・ml・`•` の箇条・負の数の読み取り（E-113）
- 登録画面の検索欄への言い換えの表の適用（貼り付けの当てはめに限る）
- 炭水化物の判定の規則・主食の比率・基準値の変更（本人が直し方を選ぶまで。E-112）
- NFR-01 を本人以外で確かめること（E-111）
- SRS 7 章の将来の要求（外食の記録、端末間の同期など）
