# 画面設計メモ

weekmeal の今後の画面構成と、各画面に置きたい機能のメモです。

画面間の移動は [画面遷移図](screen-flow.md) にまとめています。
スーパーの売場分類を検討するための外部資料は [スーパーマーケットの売場分類・運営に関する参考資料](references/supermarket-shelves.md) にまとめています。
栄養データ・表示名・棚配置の分離方針は [データ設計](data-design.md) にまとめています。

## ホーム画面

- 登録した食材だけを使って栄養サマリを表示する
- ほかの画面への遷移を置く
- 食品データベースの食品はホーム集計に混ぜない
- 最初に見る画面として、登録済み食材の栄養状態をざっくり把握できるようにする

## 食品一覧画面

- 文科省データの食品を検索・表示する
- 食品を選択して栄養詳細画面へ遷移できるようにする
- ホーム画面とは分けて、食品データベース閲覧用の画面にする

## 食材登録画面

- 入力モードを「簡易」と「詳細」で切り替えられるようにする
- 簡易モードを初期状態とし、一般的な食材名を1回押すと代表データで登録する
- 詳細モードでは文科省の正式名称・状態・食品番号を表示し、個別の食品データを選んで登録する
- 棚の分類と検索語は両モードで共通に使う
- 食材名を検索し、同じ食材の文科省データをひとつにまとめて表示する
- 文科省名に「（あじ類）」のような分類がある場合は、まあじ・にしまあじ・しまあじ等を「あじ」にまとめる
- 「（その他）」「（でん粉製品）」のような分類ラベルは食材名として表示せず、その後ろの実際の食品名を使う
- 分類表記がない例外は `src/data/foodDisplayNames.ts` の別名設定で同じグループへまとめる
- 玉ねぎ・じゃがいもなどの食材を押すだけで登録を完了する
- 状態・部位・量は通常の登録時に選ばせない
- 生・ゆで・焼き・蒸しなどがある場合は、原則として「生」の代表データを自動的に使用する
- 栄養値が大きく変わり、スーパーで別の商品として認識されるものは別項目にする
  - `鶏肉` と `鶏のから揚げ`
  - `じゃがいも` と `フライドポテト`
  - 生鮮品と漬物・缶詰・乾燥品
- 文科省の正式名称と100g当たりの栄養値は変更せず保持する
- 次のスーパーの棚で候補を絞り込めるようにする
  - 野菜
  - 果物
  - 魚
  - 肉
  - 卵
  - 豆腐・納豆
  - 乳製品
  - 米・パン・麺
  - 惣菜
  - 冷凍食品
  - 飲み物
  - お菓子
  - 調味料
  - その他
- アプリ上の「野菜」には、野菜類・きのこ類・いも類を含める
- 文科省の「いも及びでん粉類」のうち、でん粉・でん粉製品は野菜に含めない
- 卵は独立した棚とし、鶏卵とうずら卵などを同じ棚に置く
- 野菜と果物、卵と豆腐・納豆と乳製品は、それぞれ別の棚として扱う
- こんにゃくは乾燥品を含めて「豆腐・納豆」に置く
- 「〇〇の漬物」と表示する食品は「豆腐・納豆」に置く
- かに風味かまぼこは「豆腐・納豆」に置く
- えんどうは、アプリでは「えんどうまめ」と表示する
- うめとアボカドは「野菜」に置く。ただし、梅漬けなどの漬物は「豆腐・納豆」を優先する
- 果実類の「かき」は「柿」と表示し、魚介類の牡蠣には影響させない
- さくらんぼ、ブルーベリー、メロンは「よくある」として優先表示する
- しいたけの乾燥品、えだまめ、いんげんまめ、えんどうまめ、かぶは「よくある」として優先表示する
- 文科省の「液状乳類」は、アプリでは「牛乳」と表示し、普通牛乳を代表データにする
- アイスクリーム・アイスミルク・ラクトアイス・ソフトクリーム・シャーベットは「冷凍食品」に置く
- クリーム・ヨーグルト・乳酸菌飲料は、スーパーでよくある食品として優先表示する
- コーラなど文科省データに存在しない商品は、画面用に架空のデータを追加しない
- どの棚にも分類されない食品は「その他」に表示する
- 食品ごとの例外的な棚配置は `src/data/foodShelfOverrides.ts` で管理し、通常の分類より優先する
- 未検索時は、一般的なスーパーで見つけやすい食材を先に表示する
- 優先食材は `src/data/supermarketFoods.ts` で管理し、地域や季節に応じて変更できるようにする
- 優先対象ではない食材も一覧の後半と検索結果には表示する
- 使用量の入力・換算は現段階では扱わない
- 内部計算では暫定的に100g当たりの値をそのまま使用する
- 手入力で食材を登録できるようにする
- 手入力時は上記のスーパーの棚からカテゴリを選択する
- 一覧の食材を1回押すだけで登録できる導線にする

## 栄養詳細画面

- 栄養情報を詳しく表示する
- 基本栄養素を表示する
- 文科省データから取り込んだビタミン・ミネラルまで表示する
- 足りない栄養素を強調する

## 将来構想: レシート入力

現時点では実装せず、今後検討する機能として残す。

### 目的

- 毎食を入力するのではなく、買い物レシートから食材をまとめて簡単に登録できるようにする
- 「レシートを1枚撮れば、大体の入力が終わる」体験を目指す
- 正確な摂取記録ではなく、1週間に買った食材の傾向を大体つかむ

### 想定する流れ

1. レシートを撮影または画像から選択する
2. 商品名を読み取る
3. 商品名を一般的な食材名へまとめる
   - `国産若どりモモ肉` → `鶏肉`
   - `長野県産ぶなしめじ` → `しめじ`
   - `真あじ開き` → `あじ`
   - `北海道牛乳1000ml` → `牛乳`
4. 読み取り結果の間違いや不明な商品だけ確認する
5. 複数の食材をまとめて登録する

### 数量の扱い

- レシートに重量がない商品は、グラム入力を強制しない
- `1パック`、`1袋`、`2枚`、`1本`など、レシートから分かる単位を優先する
- 栄養の概算が必要な場合は、標準量へ換算する
- 標準量による換算は概算であることを明示し、必要な場合だけ修正できるようにする

### 表示上の注意

- レシートで分かるのは「買ったもの」であり、「食べたもの」ではない
- レシート入力だけを根拠に「摂取カロリー」「栄養不足」と断定しない
- 結果は「今週買った食材」「買い物の傾向」「冷蔵庫にありそうな食材」などとして表示する
- 食品ではない商品は自動的に除外し、不明な商品だけ利用者に確認してもらう

## 実装時の考え方

- まずはホーム画面を起点に、食材登録画面と栄養詳細画面へ遷移できる形にする
- 食材登録は最初から複雑にしすぎず、カテゴリ選択と最低限の栄養入力から始める
- 栄養詳細は、基本栄養素から始めて、あとでビタミン・ミネラルを広げる
- 不足の強調は、基準値をどこから持つかを決めてから実装する
